# 🌐 net-probe

> 一支只用 macOS 內建工具寫成的「網路品質體檢」腳本：同時對 4 個網路位址測試，Ctrl+C 後給你一張成績單。
> *A zero-dependency macOS shell script that pings 4 targets in parallel and grades your connection.*

## 這是什麼？（白話版）

你有沒有遇過這種情況：

- 視訊會議突然卡住、聲音斷斷續續，但網路圖示明明是滿格？
- 打電動「Lag」，卻不知道是自己家網路、還是遊戲伺服器的問題？
- 打電話給網路公司客服，對方說「我們這邊測起來正常」？

**net-probe 就是幫你「用數據說話」的小工具。**

它的做法很像「對著山谷大喊，聽回音要多久」：

| 比喻 | 技術名詞 | 意思 |
|---|---|---|
| 喊一聲，回音多久回來 | **延遲 Latency（ms）** | 資料來回一趟的時間，越小越好 |
| 回音有時快、有時慢 | **抖動 Jitter（ms）** | 延遲的忽快忽慢程度，越小越穩 |
| 喊了但沒聽到回音 | **丟包 Packet Loss（%）** | 資料中途不見的比例，越低越好 |

程式會**每秒同時對 4 個位址各喊一次話**，持續記錄。你想結束時按 `Ctrl + C`，它就會：

1. 算出每個位址的延遲、抖動、丟包率，並打分數（0–100）。
2. 再實際下載一個 100 MB 的檔案，測試真實的下載品質（IPv4 與 IPv6 各一次）。
3. 告訴你哪一條路徑最穩。

預設的 4 個測試對象：

| 名稱 | 位址 | 是什麼 |
|---|---|---|
| TWNIC | 101.101.101.101 | 台灣網路資訊中心的公共 DNS |
| HiNet | 168.95.1.1 | 中華電信 DNS |
| Cloudflare | 1.1.1.1 | Cloudflare 公共 DNS |
| GoogleDNS | 8.8.8.8 | Google 公共 DNS |

> 💡 為什麼選 DNS 伺服器？因為它們全年無休、非常穩定，拿來當「量尺」最適合。
> 想改成你常用的網站或遊戲伺服器？見 [FAQ](#常見問題-faq)。

## 快速開始（3 步驟）

> 不需要安裝任何東西。你的 Mac 本來就有 `ping`、`curl`、`bash`。

**① 打開「終端機」**
按 `⌘ + 空白鍵`，輸入 `終端機`（或 `Terminal`），按 Enter。

**② 下載並進入資料夾**

```bash
git clone https://github.com/WebberningMoney/net-probe.git
cd net-probe
```

> 不會用 git？到 GitHub 頁面按綠色 **Code → Download ZIP**，解壓縮後在終端機輸入 `cd ` 再把資料夾拖進視窗、按 Enter。

**③ 執行**

```bash
chmod +x net_probe.sh     # 第一次需要：允許這支檔案被執行
./net_probe.sh
```

讓它跑一段時間（建議至少 5 分鐘；想抓「晚間尖峰」問題就跑 1 小時以上），然後按 **`Ctrl + C`** 看報告。

**進階：自訂下載測速檔**

```bash
./net_probe.sh "https://你的測速網址/檔案.bin"

# 網速較慢？把下載最長時間從 60 秒加大：
CURL_MAX_TIME=120 ./net_probe.sh
```

## 怎麼看懂結果？

### Ping 表格

| 欄位 | 白話解釋 | 怎樣算好？ |
|---|---|---|
| **Count** | 一共測了幾次 | 越多越可信 |
| **Lost / Loss%** | 掉了幾次 / 掉包比例 | 理想 0%；超過 1% 就可能影響通話 |
| **Avg** | 平均來回時間（毫秒） | 台灣境內 < 30 ms 很棒 |
| **Min / Max** | 最快 / 最慢的一次 | Max 遠大於 Avg 代表偶爾卡頓 |
| **Jit** | 抖動：忽快忽慢程度 | 越低越好；視訊/遊戲對它很敏感 |
| **Score / Grade** | 綜合分數與等級 | 見下表 |

### 等級

| 色塊 | 等級 | 分數 | 感受 |
|---|---|---|---|
| 🟩 | Excellent | ≥ 90 | 幾乎沒有煩惱 |
| 🟨 | Good | 75–89 | 日常使用順暢 |
| 🟧 | Moderate | 60–74 | 偶爾會感覺到卡頓 |
| 🟥 | Poor | < 60 | 明顯有問題 |

### Curl 表格（真實下載）

| 欄位 | 白話解釋 |
|---|---|
| **DNS** | 把網址翻譯成 IP 花多久（像查電話簿） |
| **TCP** | 跟對方「接上線」花多久（像撥通電話） |
| **SSL** | 建立加密通道花多久（像確認對方身分） |
| **TTFB** | 對方開始回傳第一個資料要多久 |
| **Total** | 100 MB 全部下載完花多久 |
| **Speed** | 平均下載速度 |
| **HTTP** | 伺服器回應碼，`200` 代表成功 |

**IPv4 vs IPv6**：兩種不同的「門牌系統」。程式會各測一次，看哪個比較快。
若你的網路沒有 IPv6，程式會自動略過，不是故障。

## 分數是怎麼算的？

**Ping 分數**

```text
Score = 100 − ( 丟包率% × 2  +  平均延遲 ÷ 2  +  抖動 × 1.5 )
```

例：丟包 0%、平均 20 ms、抖動 3 ms → 100 − (0 + 10 + 4.5) = **85.5 分**。
丟包扣得最重（每 1% 扣 2 分），因為它對使用體驗傷害最大。

**Curl 分數**

```text
Score = 100 − 7 × [ ln(1+DNS×5) + ln(1+TCP×3) + ln(1+SSL×3) + ln(1+Total×6) ]
```

用對數（ln）的好處：很慢時扣分會「趨緩」，不會一次就扣到 0。
*這是作者依個人體感設計的經驗公式，並非業界標準，請當作「相對比較」使用。*

## 產生了哪些檔案？

每次執行會在**執行時所在的資料夾**建立 4 個紀錄檔：

```text
ping_TWNIC_20251031_141204.log
ping_HiNet_20251031_141204.log
ping_Cloudflare_20251031_141204.log
ping_GoogleDNS_20251031_141204.log
```

內容是 CSV（可用 Excel / Numbers / Google 試算表 開啟）：

```csv
time,seq,latency(ms)
2025-10-31 14:12:05,1,19.8
2025-10-31 14:12:06,2,timeout
```

> 這些 `.log` 檔已被 `.gitignore` 排除，不會被誤傳到 GitHub。

## 常見問題 FAQ

**Q：執行時出現 `Permission denied`？**
A：忘了加執行權限。輸入 `chmod +x net_probe.sh` 再試一次。

**Q：出現 `This script is macOS-only`？**
A：這是刻意設計，因為用到 macOS 專屬指令。Windows / Linux 暫不支援。

**Q：為什麼 IPv6 被略過？**
A：你的網路（或路由器）沒有分配 IPv6，屬正常情況。

**Q：怎麼改測試目標？**
A：用文字編輯器開啟 `net_probe.sh`，找到 `第 1 區` 的 `TARGETS` 與 `NAMES` 兩行，**兩邊順序要對應**地修改。例如把 `8.8.8.8` 換成你常連線的遊戲伺服器 IP。

**Q：可以長時間掛著跑嗎？**
A：可以。電腦睡眠醒來後的第一輪資料會自動丟棄，不影響分數。

**Q：它會傳送我的資料嗎？**
A：只有兩個對外連線：① 啟動時向 `ipinfo.io` 查詢你的 ISP 名稱；② 結束時向 `speed.cloudflare.com`（預設）下載測試檔。其餘都是對那 4 個 IP 的 ping。程式不會上傳你的檔案。

## 已知問題

v4.6 修正了原版 v4.5 的 8 個問題。修正後以「假的 macOS 指令」在 Linux 上做過端對端測試（模擬斷線、逾時、睡眠），**但尚未在真正的 Mac 上實測**，見下方「請你驗證」。

| 編號 | 原本的問題 | 現在 | 驗證 |
|---|---|---|---|
| KI-1 | 統計時 CSV 表頭被當成一筆資料，`Count` 多 1、丟包率偏低（4 筆含 1 次 timeout 應為 25%，算出 20%） | ✅ 已修正 | 以同一份測試資料重跑，得 25.00% |
| KI-2 | 睡眠偵測只計數，沒有真正剔除，但報表卻寫「已自動排除」 | ✅ 偵測到睡眠就丟棄醒來後那一輪（不寫 log） | 模擬時鐘跳 100 秒，log 中該輪確實沒有資料 |
| KI-3 | `ping` 沒有逾時，目標斷線會拖慢整輪 | ✅ 加上 `-W`（毫秒）與 `-t`（秒） | ⚠️ 旗標依 macOS man page 撰寫，需在 Mac 驗證 |
| KI-4 | 查詢 ISP 的 `curl` 沒有逾時 | ✅ 最多等 5 秒，失敗顯示 Unknown | 模擬測試 |
| KI-5 | 結尾報表用 `tee /dev/tty`，無終端機時出錯 | ✅ 改用暫存檔 | 在無 tty 環境完整跑完 |
| KI-6 | `PING_TIMEOUT_SEC`、`PROGRESS_BAR_SEC` 是未使用的殘留參數 | ✅ 前者現在真的生效，後者已移除 | 程式碼檢查 |
| KI-7 | Curl 固定最長 30 秒，慢速網路下載不完、分數失真 | ✅ 改為 60 秒（可用 `CURL_MAX_TIME` 覆寫），逾時會在報表加註警告 | 模擬 IPv6 逾時，警告正常顯示 |
| KI-8 | 🆕 log 的 `seq` 欄永遠是 1（並行時在背景子行程累加，父行程看不到） | ✅ 改由父行程計算再傳入 | log 中 seq 依序為 1、2、3、4、5 |

**睡眠門檻也一併調整**：原本是 3 秒，但目標斷線時一輪就可能超過 3 秒而被誤判為睡眠，現改為 10 秒（`SLEEP_GAP_THRESHOLD`）。

### 🧪 請你在 Mac 上驗證（約 1 分鐘）

```bash
# 1. ping 逾時旗標：應該在約 1~2 秒內結束，而不是卡很久
time ping -n -c 1 -W 1000 -t 2 10.255.255.1

# 2. 完整跑一次，看報表是否正常
./net_probe.sh        # 跑 30 秒後按 Ctrl+C
```

若第 1 步出現 `illegal option`，請回報你的 macOS 版本，我會調整旗標。

### 仍存在的限制

- 「Curl 綜合總結」是靠 `grep/sed` 反向解析前面印出的文字，**改動報表格式前務必看註解**，否則總結會顯示 `Unknown / N/A`。
- 按下 `Ctrl+C` 時若正好有一輪 ping 進行中，各目標的最後一筆樣本可能略有出入（最多差 1 筆）。
- ICMP ping 不一定等於你實際上網的感受（部分設備會對 ICMP 特別處理），建議搭配 Curl 結果一起看。

## 想學程式？從哪裡開始讀

打開 `net_probe.sh`，檔案最上方有「**整體流程圖**」與「**閱讀方式**」。建議順序：

0. **想看 bug 是怎麼修的？** 比對 `legacy/` 的原版與本檔，搜尋註解中的 `🛠 FIXED`。
1. **頂部流程圖** → 先知道程式在做什麼。
2. **第 1 區 參數** → 試著改改看目標 IP。
3. **第 4 區 `do_ping_once` / `do_ping_cycle_parallel`** → 理解「背景執行 `&` + `wait`」如何做到並行。
4. **第 6 區 `summarize_file`** → 看 `grep` + `awk` 如何當小型資料庫用。
5. **第 8–9 區** → `printf` 對齊、`trap` 攔截 Ctrl+C。

註解中的符號：`💡` 觀念、`🔰` 初學者小教室、`⚠️ KNOWN ISSUE` 已知問題。
