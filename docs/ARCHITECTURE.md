# 本機網頁儀表板：架構與技術選型（v1，已依作者決定更新）

> 狀態：**提案，尚未實作**。等作者確認「待決事項」後才開始寫程式。
> 現有的 `net_probe.sh`（Bash 版）不受影響，會繼續保留。

## 1. 要做什麼

在現有腳本的基礎上，新增一個**本機網頁儀表板**，包含四項擴充：

| # | 擴充項目 | 解決什麼問題 |
|---|---|---|
| 1 | **穩健統計 + MOS 分數**（中位數、p95、MOS） | 現行分數被少數尖峰拉得很重（實測：排除 3–5% 尖峰後分數從約 70 回到約 82） |
| 2 | **路由器（閘道）ping** | 區分問題在 Wi-Fi／路由器，還是在 ISP 之後 |
| 3 | **告警通知** | 延遲或丟包超標時主動提醒，不必一直盯著畫面 |
| 4 | **歷史趨勢圖** | 看「什麼時段」變差，方便和網路公司溝通 |

## 2. 它在哪裡執行？

**就在你自己的 Mac 上，不是網站、不上雲端。**

```text
┌────────────────────── 你的 Mac ──────────────────────┐
│                                                      │
│  終端機：python3 dashboard.py                        │
│     │                                                │
│     ├─ 每秒呼叫系統 ping（4 個目標 + 路由器）        │
│     ├─ 結果寫入本機資料庫（SQLite 檔案）             │
│     └─ 在 http://127.0.0.1:8765 提供網頁             │
│                         ▲                            │
│  瀏覽器（Safari/Chrome）─┘  開啟上面的網址看儀表板   │
└──────────────────────────────────────────────────────┘
```

- **啟動**：在終端機執行一行指令，程式會自動用瀏覽器打開儀表板。
- **關閉**：在終端機按 `Ctrl + C`（或關掉終端機視窗），監測就停止。
- **只對本機開放**：綁定 `127.0.0.1`，同一個 Wi-Fi 的其他裝置連不到。
- **資料留在你的電腦**：沒有帳號、沒有雲端、沒有追蹤。唯一對外的連線是 ping 目標，以及（選用）Cloudflare 下載測速與 ipinfo 查詢 ISP。
- **想開機自動跑？** 之後可選用 macOS 的 launchd 設定，不在第一版範圍。

## 3. 技術選型（推薦）

核心原則延續本專案：**零安裝、容易讀懂、適合學習**。

| 層級 | 推薦 | 理由 | 備選（取捨） |
|---|---|---|---|
| 後端語言 | **Python 3.13**（作者環境 3.13.5） | 語法易讀，適合當教材；作者已同意使用 `pip install` | Node.js（需另裝）、Go/Swift（編譯較複雜） |
| 網頁伺服器 | **FastAPI + uvicorn**（裝在專案專用的 venv，版本固定於 requirements.txt） | 現代、SSE 與 API 寫法簡潔；venv 與系統／conda 環境隔離，不污染也不受干擾 | 標準庫 `http.server`（零安裝但程式較冗長） |
| 取得 ping | 呼叫系統 `ping`（`subprocess`） | 不需 root 權限；沿用已在 Mac 驗證過的 `-W/-t` 旗標 | 自己送 ICMP（需 root，不建議） |
| 即時更新 | **SSE**（Server-Sent Events） | 單向推送，比 WebSocket 簡單，FastAPI 內建支援 | 每秒輪詢（最簡單，稍微浪費） |
| 資料庫 | **SQLite**（標準庫 `sqlite3`） | 單一檔案、免安裝、可查詢歷史、可匯出 CSV | 繼續只用 CSV（難做區間查詢與彙總） |
| 前端 | **單一 HTML + 原生 JavaScript** | 無建置步驟（不用 npm / webpack），打開就能改 | React/Vue（需建置工具，對本專案過重） |
| 圖表 | **Chart.js**（把檔案放進 repo，離線可用） | 易學、文件多、MIT 授權 | uPlot（效能更好，適合超長時間序列，但 API 較不直覺） |
| 通知 | macOS `osascript`（系統通知中心）＋瀏覽器通知 | 免安裝；關著瀏覽器也能通知 | 第三方推播（需帳號，違背零安裝） |

### 為什麼不繼續用 Bash 做這個？
Bash 很適合「一次性報告」，但做**即時網頁、資料庫、圖表、通知**會變得難讀又難測。改用 Python 後，`net_probe.sh` 仍保留給喜歡單檔腳本的人。

## 4. 資料流

```text
ping 執行緒 ×5 ──► 取樣佇列 ──► SQLite（原始樣本 + 每分鐘彙總）
 （4 目標＋路由器）        │
                           ├──► 統計模組（中位數／p95／抖動／丟包／MOS）
                           │         │
                           │         ├──► 告警規則 ──► macOS 通知／網頁橫幅
                           │         └──► SSE 推送 ──► 瀏覽器即時圖表
                           └──► 歷史查詢 API ──► 趨勢圖（5 分鐘 / 1 小時 / 24 小時 / 7 天）
```

## 5. 四項擴充的設計重點

**① 穩健統計 + MOS**
- 顯示中位數、p95、p99、抖動、丟包，**同時保留**現行 Score 以便和 Bash 版對照。
- MOS 採用常見的 E-model 簡化近似（由延遲、抖動、丟包換算為 1–5 分）。實作時會標明公式出處，並用固定測試案例驗證數值。

**② 路由器 ping**
- 以 `route -n get default` 取得閘道位址，作為第 5 個目標。
- 儀表板並排顯示「路由器 vs 外部目標」，並提供判讀提示：
  - 路由器本身就有尖峰 → 問題偏向 Wi-Fi／路由器。
  - 路由器正常、外部目標有尖峰 → 問題偏向路由器之後（ISP 或遠端）。

**③ 告警**
- 規則範例：近 1 分鐘丟包率超過門檻、p95 超過門檻、目標連續逾時、路由器不通。
- 門檻可在設定檔調整；內建「冷卻時間」避免連續轟炸通知。

**④ 歷史趨勢**
- 原始每秒樣本只保留一段時間，更久的資料保留「每分鐘彙總」（平均／p95／丟包／樣本數）。
- 可選時間範圍，並可匯出 CSV。

## 7. 驗證策略（誠實說明限制）

- 開發環境不是 macOS，因此：**統計、MOS、彙總、告警邏輯**會用假資料做自動化測試；**真實 ping 與系統通知**需要在作者的 Mac 上手動驗證。
- 每個功能完成後提供「Mac 驗證清單」（幾行指令加預期結果），延續本專案已採用的做法。

## 8. 已定案的決策

1. 技術軸：Python 3.13 + FastAPI + uvicorn（venv）+ SQLite + 原生 JS + Chart.js。啟動腳本自動建立 venv 並安裝 `requirements.txt`。
2. 資料保留：原始樣本 24 小時；每分鐘彙總 90 天。
3. 介面語言：繁體中文。
4. 第一版目標清單只改 `config.json`，網頁上不編輯。
5. 儀表板含 Curl 下載測速（手動按鈕＋可選的定期執行，預設關閉）。
6. 測試模式：「持續監測」與「定時測試 N 分鐘」兩種皆提供（與 Bash 版 v4.9 的時長選擇一致）。
7. 開發順序：Phase 1 Bash 時長選擇 → Phase 2 儀表板核心 → Phase 3 路由器 ping 與告警 → Phase 4 網頁介面與歷史趨勢。
8. 服務只綁定 127.0.0.1（預設埠 8765），不對外開放。
