# 命令列體檢腳本 `net_probe.sh` 完整說明

> 這是 NetSonar 的前身：一支在終端機執行的腳本，量一段時間後印出一張「網路成績單」。
> 不用安裝 Python，Mac 本來就有它需要的工具（`ping`、`curl`、`bash`）。
> 想要「一直在背景量、隨時打開網頁看」，請用 NetSonar 儀表板（見 [README](../README.md)）。

---

## 1. 它做什麼？

1. **同時對 4 個地方每秒各「喊」一聲**（ping），記下多久有回音、有沒有回音。
2. 時間到（或你按 `Ctrl + C`），算出每個目標的延遲、抖動、丟包，打 0～100 分。
3. 再**實際下載一個約 90 MB 的測試檔**，看真實的下載狀況（IPv4、IPv6 各一次）。
4. 告訴你哪一條路線最穩。

預設的 4 個測試對象（都是全年無休、非常穩定的公共 DNS 伺服器，很適合當「量尺」）：

| 名稱 | 位址 | 是什麼 |
|---|---|---|
| TWNIC | 101.101.101.101 | 台灣網路資訊中心 |
| HiNet | 168.95.1.1 | 中華電信 |
| Cloudflare | 1.1.1.1 | Cloudflare |
| GoogleDNS | 8.8.8.8 | Google |

## 2. 怎麼執行

**① 打開「終端機」**：按 `⌘ + 空白鍵`，輸入 `終端機`（或 `Terminal`），按 Enter。

**② 進到專案資料夾**（假設放在桌面）：

```bash
cd ~/Desktop/net-sonar
```

> 用 ZIP 下載的話：輸入 `cd `（cd 後面有一個空格），再把資料夾從 Finder 拖進終端機視窗，按 Enter。

**③ 執行**：

```bash
chmod +x net_probe.sh     # 只有第一次需要：允許這個檔案被執行
./net_probe.sh
```

啟動後會先問你要測多久：

```
🔧 要測多久？
  1) 5 分鐘（約 272 輪）  ← 預設
  2) 15 分鐘
  3) 1 小時
  4) 自訂（輸入分鐘數或輪數）
  5) 持續測試，按 Ctrl+C 結束
請選擇 [1-5，直接按 Enter = 1]：
```

不確定就直接按 **Enter**（測 5 分鐘）。想抓「晚上網路比較慢」的問題，可以選 1 小時以上。
時間一到會自動做下載測試（約十幾秒到一分鐘），然後印出總結。中途想提早看報告，隨時按 **`Ctrl + C`**。

**之後再用**：每次打開新的終端機視窗，都要先 `cd ~/Desktop/net-sonar`，再 `./net_probe.sh`。

- 出現 `No such file or directory`：代表你不在專案資料夾裡，先 `cd ~/Desktop/net-sonar`。（`pwd` 看目前在哪裡，`ls` 看這裡有哪些檔案。）
- 紀錄檔（`.log`）會存在你執行時所在的資料夾。想在 Finder 打開這個資料夾：輸入 `open .`。

### 進階選項

```bash
./net_probe.sh -d 15          # 直接測 15 分鐘，不顯示選單
./net_probe.sh -n 300         # 測 300 輪（1 輪約 1.1 秒）
./net_probe.sh --forever      # 一直測，按 Ctrl+C 結束
./net_probe.sh --no-curl      # 結束時不做下載測試（比較快）
./net_probe.sh -h             # 顯示完整說明

./net_probe.sh "https://你的測速網址/檔案.bin"   # 換一個下載測試檔
CURL_MAX_TIME=120 ./net_probe.sh                  # 網速慢時，把下載最長時間從 60 秒加大到 120 秒
```

## 4. 怎麼看懂結果？

### Ping 表格

| 欄位 | 白話 | 怎樣算好？ |
|---|---|---|
| **Count** | 一共量了幾次 | 越多越可信 |
| **Lost / Loss%** | 沒回應幾次／比例（丟包） | 理想 0%；超過 1% 就可能影響通話 |
| **Avg** | 平均來回時間（毫秒） | 台灣境內 30 ms 以下很好 |
| **Min / Max** | 最快／最慢的一次 | Max 遠大於 Avg，代表偶爾會卡一下 |
| **Jit** | 抖動：忽快忽慢的程度 | 越低越好；視訊、遊戲對它很敏感 |
| **Score / Grade** | 綜合分數與等級 | 見下表 |

| 色塊 | 等級 | 分數 | 感受 |
|---|---|---|---|
| 🟩 | Excellent | 90 以上 | 幾乎沒有煩惱 |
| 🟨 | Good | 75～89 | 日常使用順暢 |
| 🟧 | Moderate | 60～74 | 偶爾會感覺卡 |
| 🟥 | Poor | 60 以下 | 明顯有問題 |

### 問題在「我這邊」還是「對方那邊」？

看紀錄檔時有個很有用的線索：**同一秒，四個目標是不是一起變慢？**

- **只有某一個目標變慢** → 通常是那個目標（或通往它的路線）的問題。
- **四個目標在同一秒一起變慢** → 它們共同經過的那一段有狀況：你的 Wi-Fi、路由器，或網路公司接到你家的線路。四個目標本身不太可能同時出問題。

想更確定的話，用 NetSonar 儀表板：它會同時量你家的路由器，直接告訴你問題在哪一段。

### Curl 表格（真實下載）

| 欄位 | 白話 |
|---|---|
| **DNS** | 把網址翻成數字位址花多久（像查電話簿） |
| **TCP** | 跟對方接上線花多久（像撥通電話） |
| **SSL** | 建立加密連線花多久（像確認對方身分） |
| **TTFB** | 對方開始傳資料回來要多久 |
| **Total** | 整個檔案下載完花多久 |
| **Speed** | 平均下載速度 |

**IPv4 和 IPv6**：兩種不同格式的網路門牌。程式會各測一次，看哪個快。你的網路沒有 IPv6 的話會自動略過，不是故障。

## 5. 分數是怎麼算的？

**Ping 分數**

```text
分數 = 100 − ( 丟包率% × 2  +  平均延遲 ÷ 2  +  抖動 × 1.5 )
```

例：丟包 0%、平均 20 ms、抖動 3 ms → 100 − (0 + 10 + 4.5) = **85.5 分**。
丟包扣最重（每 1% 扣 2 分），因為它對使用感受傷害最大。

**Curl 分數**

```text
分數 = 100 − 7 × [ ln(1+DNS×5) + ln(1+TCP×3) + ln(1+SSL×3) + ln(1+Total×6) ]
```

`ln`（自然對數）的作用：很慢的時候扣分會「趨緩」，不會一下子就扣到 0。
*這是作者依個人感受設計的公式，不是業界標準，請當作「互相比較」用。*

## 6. 會產生哪些檔案？

每次執行會在**執行時所在的資料夾**建立 4 個紀錄檔，例如：

```text
ping_TWNIC_20251031_141204.log
ping_HiNet_20251031_141204.log
ping_Cloudflare_20251031_141204.log
ping_GoogleDNS_20251031_141204.log
```

內容是 CSV 格式（可用 Excel、Numbers、Google 試算表打開）：

```csv
time,seq,latency(ms)
2025-10-31 14:12:05,1,19.8
2025-10-31 14:12:06,2,timeout
```

> 這些 `.log` 檔已設定為不會上傳到 GitHub（`.gitignore`）。

## 7. 常見問題

**Q：出現 `Permission denied`？**
A：還沒允許這個檔案被執行。輸入 `chmod +x net_probe.sh` 再試一次。

**Q：出現 `This script is macOS-only`？**
A：刻意的設計，因為用到 Mac 專屬的指令。Windows、Linux 不支援。

**Q：Curl 表格顯示 `❌ HTTP 403`（或其他不是 200 的數字）？**
A：下載被伺服器拒絕，這次下載測試不算分。可以換一個測速網址：`./net_probe.sh "https://你的測速網址/檔案.bin"`。Ping 的結果不受影響。

**Q：為什麼 IPv6 被略過？**
A：你的網路沒有分配 IPv6，很常見，不是故障。

**Q：怎麼改測試目標？**
A：用文字編輯器打開 `net_probe.sh`，找到「第 1 區」的 `TARGETS` 和 `NAMES` 兩行，**兩邊順序要對應**地修改。

**Q：可以長時間一直跑嗎？**
A：可以。電腦睡眠醒來後的第一輪資料會自動丟掉，不影響分數。

**Q：它會傳送我的資料嗎？**
A：只有兩個對外連線：① 啟動時向 `ipinfo.io` 查你的網路公司名稱；② 結束時向 `speed.cloudflare.com` 下載測試檔。其他都只是對那 4 個位址 ping。不會上傳你的任何檔案。

## 8. 已修正的問題（給有興趣的人）

v4.8 修正了原版 v4.5 的 12 個問題，全部已在真實 Mac（macOS 27.0.1）驗證。

| 編號 | 原本的問題 | 怎麼修 |
|---|---|---|
| KI-1 | 統計時把表頭也當成一筆資料，次數多 1、丟包率偏低 | 跳過表頭 |
| KI-2 | 偵測到電腦睡眠，卻沒有真的丟掉醒來後那一輪 | 真的丟掉 |
| KI-3 | ping 沒有等待上限，目標斷線會拖慢整輪 | 加上等待上限 |
| KI-4 | 查網路公司名稱沒有等待上限 | 最多等 5 秒，失敗顯示 Unknown |
| KI-5 | 沒有終端機畫面的環境下，報表會出錯 | 改用暫存檔 |
| KI-6 | 有兩個設定值其實沒在用 | 一個改成真的生效，一個移除 |
| KI-7 | 下載最多只等 30 秒，網速慢時下載不完、分數失真 | 改成 60 秒（可調），逾時會在報表註明 |
| KI-8 | 紀錄檔的流水號永遠是 1 | 改由主程式計算 |
| KI-9 | 下載失敗（HTTP 403）反而拿到高分 | 失敗一律不計分 |
| KI-10 | 沒有 IPv6 或兩邊同分時，總結顯示錯誤 | 各種情況都正確顯示 |
| KI-11 | 新版 macOS 的版本名稱顯示錯誤 | 直接向系統詢問版本 |
| KI-12 | 預設下載大小被 Cloudflare 拒絕（必須小於 1 億位元組） | 改成 9000 萬位元組 |

另外：判斷「電腦剛睡醒」的門檻從 3 秒改成 10 秒，避免目標斷線時被誤判。

**仍存在的限制**

- 「Curl 綜合總結」是讀取前面印出的文字來判斷的，**改動報表格式前要先看註解**，否則總結會顯示 `Unknown`。
- 按下 `Ctrl + C` 時如果剛好在量測中，各目標的最後一筆可能差 1 筆。
- ping 不一定完全等於你上網的感受（有些設備會特別處理 ping），建議搭配下載測試一起看。

## 9. 想學程式？從哪裡開始讀

打開 `net_probe.sh`，最上面有「整體流程圖」和「閱讀方式」。建議順序：

1. **最上方的流程圖** → 先知道程式在做什麼。
2. **第 1 區：參數** → 試著改改看目標位址。
3. **第 4 區：`do_ping_once`、`do_ping_cycle_parallel`** → 看「同時 ping 4 個目標」是怎麼做到的（`&` 讓指令在背景跑，`wait` 等它們全部跑完）。
4. **第 6 區：`summarize_file`** → 看 `grep` 和 `awk` 怎麼像小型資料庫一樣做統計。
5. **第 8～9 區** → 怎麼把表格對齊、怎麼在按 `Ctrl + C` 時改成印出報告。

想看 bug 是怎麼修的：拿 `legacy/` 裡的原版跟 `net_probe.sh` 比對，搜尋註解裡的 `🛠 FIXED`。

註解中的符號：`💡` 觀念說明、`🔰` 初學者小教室、`🛠 FIXED` 已修正的問題。
